> 配套文档：[01-设计思路.md](./01-设计思路.md)（决策理由）、[03-复现指南.md](./03-复现指南.md)（算法公式与实现步骤）

## 1. 架构总览

```
                        ┌─────────────────────────────────────────────┐
                        │              Agent 决策链路（后端）           │
                        │                                             │
  football-data.org ──► │ ┌──────────┐  ┌──────────┐  ┌────────────┐ │
  eloratings.net    ──► │ │Collector │─►│ Rating   │─►│ Predictor  │ │
  FIFA 排名         ──► │ │ 数据采集  │  │ 实力评估  │  │ 单场概率预测│ │
                        │ └────┬─────┘  └──────────┘  └─────┬──────┘ │
                        │      ▼                            ▼        │
                        │ data/*.json              ┌────────────┐    │
                        │ （快照兜底）              │ Simulator  │    │
                        │                          │ 逐轮推演    │    │
                        │                          │ +蒙特卡洛   │    │
                        │                          └─────┬──────┘    │
                        │                                ▼           │
  DashScope(Qwen) ◄───► │                          ┌────────────┐    │
                        │                          │ Reasoner   │    │
                        │                          │ LLM推理解释 │    │
                        │                          └─────┬──────┘    │
                        └────────────────────────────────┼───────────┘
                                                         ▼
                                              output/prediction.json
                                                         │
                                              ┌──────────┴──────────┐
                                              │  FastAPI (api.py)   │
                                              │  REST API + 静态托管 │
                                              └──────────┬──────────┘
                                                         ▼
                                              ┌─────────────────────┐
                                              │  Vue 3 前端 SPA      │
                                              │  对阵树/积分表/概率榜 │
                                              └─────────────────────┘
```

原则：**Agent 模块单向流水线，无环依赖**；每个模块输入输出均为纯数据（dict/JSON），可独立测试、独立演示。
v1.1 起流水线外还有两条支路：Features（上下文特征，注入解释层）与 Calibrate（回测校准，写 model_params.json 反哺 Rating/Predictor）；API 层带 auto-refresh 后台调度（见 §6）。

## 3. 模块职责与接口

### 3.1 Collector（数据采集）

| 项 | 说明 |
|---|---|
| 输入 | 环境变量 `FOOTBALL_DATA_TOKEN`（可选） |
| 输出 | `TournamentData`：`{teams, groups, matches, elo_ratings, fifa_rankings}` |
| 数据源 | football-data.org `/v4/competitions/WC/matches`、eloratings.net、FIFA 排名静态表 |
| 容错 | 每次成功拉取写入 `backend/data/*.json` 快照；任何失败自动读快照并在结果中标记 `data_source: "snapshot"` |

### 3.2 Rating（实力评估）

| 项 | 说明 |
|---|---|
| 输入 | `TournamentData` |
| 输出 | `dict[team_id -> StrengthScore]`，含分项：`elo`、`fifa_rank`、`recent_form`（近期状态）、`wc_performance`（本届表现）、综合分 `overall` |
| 逻辑 | 加权融合，权重见复现指南 §3.1；纯函数，无外部调用 |

### 3.3 Predictor（单场概率预测）

| 项 | 说明 |
|---|---|
| 输入 | 两队 `StrengthScore` + 比赛属性（是否淘汰赛） |
| 输出 | `MatchPrediction`：`{p_win, p_draw, p_loss, most_likely_score, score_matrix, expected_goals}`；淘汰赛额外含 `p_advance`（含加时/点球） |
| 逻辑 | 实力差 → 期望进球 λ → 独立泊松比分矩阵（公式见复现指南 §3.2）；纯函数 |

### 3.4 Simulator（逐轮推演 + 蒙特卡洛）

| 项 | 说明 |
|---|---|
| 输入 | 当前赛况（已赛结果锁定为事实）+ Predictor |
| 输出 | ① 确定性推演：每轮每场"最可能结果"直至冠军；② 蒙特卡洛：10,000 次全赛事模拟 → `dict[team -> p_champion]` 及进入各轮概率 |
| 逻辑 | 已赛场次直接采用真实结果；未赛场次按 Predictor 概率推进。固定随机种子保证可复现 |

### 3.5 Reasoner（LLM 推理解释）

| 项 | 说明 |
|---|---|
| 输入 | 单场/冠军的全部量化依据（实力分项、历史交锋、概率结果） |
| 输出 | 中文推理文本 |
| 模型 | 单场解说 `qwen-plus`；冠军长文 `qwen-max`（DashScope OpenAI 兼容接口，`DASHSCOPE_API_KEY`） |
| 约束 | **LLM 不产生数字结论，只解释统计模型的输出**；prompt 模板见复现指南 §4 |
| 降级 | 无 key / 调用失败 → 基于规则模板生成解释，标记 `reasoning_source: "template"` |

### 3.6 Features（上下文特征，v1.1/v1.2）

| 项 | 说明 |
|---|---|
| 输入 | 推演后的 bracket（后续轮次参赛方已填充） |
| 输出 | 未赛场次的 `match.context`：`rest_days`（休息天数）、`pens_this_wc`（本届点球记录）；核心球员表加载 |
| 约束 | 特征只进解释层（Qwen 上下文 + 前端量化依据），经回测验证增益后才进评分层（docs/04） |

### 3.7 Calibrate（参数校准，v1.2）

| 项 | 说明 |
|---|---|
| 输入 | 全部已赛场次（预测用赛前实力分，无泄漏） |
| 逻辑 | 网格搜索 goal_exp × rho × elo_div × w_form，目标为平均对数损失 |
| 输出 | 改善超阈值（0.005）才写 `data/model_params.json`；predictor/rating 启动时自动加载 |

### 3.8 Pipeline（编排）

`python -m agent.pipeline` 依序执行 Collector → Rating → （Predictor+Simulator）→ Features → Reasoner，最终写 `backend/output/prediction.json`。该文件是前后端唯一契约。

## 4. API 契约（FastAPI）

| 方法 | 路径 | 说明 |
|-----|------|-----|
| GET | `/api/prediction` | 完整预测结果（prediction.json 全量） |
| GET | `/api/bracket` | 淘汰赛对阵树（含已赛真实结果与未赛预测） |
| GET | `/api/groups` | 小组赛积分表与出线情况 |
| GET | `/api/champion` | 冠军预测 + 夺冠概率 Top16 + 推理长文 |
| GET | `/api/match/{match_id}` | 单场详情：概率、比分矩阵、推理文本 |
| POST | `/api/refresh` | 重跑流水线（重新采集数据并预测） |
| GET | `/` | 前端 SPA（静态托管 `frontend/dist`） |

## 5. 前端结构

单页四个视图（顶部 Tab 切换）：

1. **对阵树**（默认页）：SVG bracket，48 队赛制（32 强→16 强→8 强→4 强→决赛）。已赛场次绿色边框 + 真实比分 + "✓"；未赛场次蓝色边框 + 预测比分 + 胜率百分比；预测晋级路径高亮到冠军。点击场次 → MatchDetail 弹窗（概率环形图 + 比分矩阵热力 + 推理文本）。
2. **小组赛**：12 组积分表，出线队高亮。
3. **夺冠概率**：Top 16 概率横向条形图，冠军金色高亮；附"进四强/进决赛/夺冠"三列概率表。
4. **冠军推理**：预测冠军大卡片 + Qwen 推理长文 + 模型回测准确率展示。

## 6. 部署架构（阿里云）

```
用户浏览器 ──HTTP:80──► 阿里云 ECS
                          └── Docker 容器（单容器）
                               └── uvicorn :8000
                                    ├── /api/*  → FastAPI
                                    └── /*      → frontend/dist 静态文件
```

- **Dockerfile 多阶段构建**：stage1 `node:20` 构建前端 → stage2 `python:3.12-slim` 装后端依赖 + 拷贝 dist + 数据快照。
- 环境变量：`DASHSCOPE_API_KEY`（Qwen）、`FOOTBALL_DATA_TOKEN`（备用数据源）、`AUTO_REFRESH_MINUTES`（自动刷新间隔，默认 30，0=关闭），均可缺省。
- `deploy/deploy-ecs.sh`：安装 docker → 构建镜像 → `docker run -d -p 80:8000`。
- **auto-refresh 后台调度（v1.1）**：服务启动即拉起 asyncio 任务，定期在线探测；发现新完赛场次 → 更新快照 → 重跑全流程 → 热替换 API 缓存。比赛日无需人工干预。

## 7. 容错与降级矩阵

| 故障 | 行为 | 用户可见性 |
|-----|------|----------|
| football-data API 失败 | 读本地快照 | 页面标注"数据快照时间" |
| DashScope 失败/无 key | 模板化规则解释 | 推理文本仍完整，标注来源 |
| 快照也缺失 | 使用仓库内置的打包快照（随代码提交） | 正常演示 |
| 前端拉 API 失败 | 显示错误态 + 重试按钮 | 明确报错 |

## 8. 测试策略

- **单元测试（pytest，26 个）**：predictor 概率自洽/对称性/DC 修正方向；simulator 固定种子可复现、已赛结果锁定、回测无泄漏；collector 快照结构与对阵行解析；features 用合成对阵树（不随赛事推进失效）；calibrate 对数损失合理区间与参数文件回读。
- **端到端**：`python -m agent.pipeline` 离线跑通（纯快照模式）→ API 各路由 200 → 前端 build 成功 → 浏览器实测四视图与弹窗。
