# 世界杯冠军预测 Agent —— 系统架构

> 配套文档：[01-设计思路.md](./01-设计思路.md)（决策理由）、[03-复现指南.md](./03-复现指南.md)（算法公式与实现步骤）

## 1. 架构总览

```
                     ┌──────────────────────── 预测流水线（backend/agent）────────────────────────┐
  Wikipedia      ──► │ Collector → Rating → Predictor → Simulator → Features → Reasoner           │
  eloratings.net ──► │ 数据采集    实力评估   单场概率     逐轮推演     上下文特征   LLM推理解释      │
  FIFA 排名      ──► │   │          ▲          ▲          +蒙特卡洛                  ▲             │
  (football-data)    │   ▼          │          │                                    │             │
                     │ data/*.json  └──── model_params.json ────┘        DashScope(Qwen)◄─────────┤
                     │ （快照兜底）        （校准参数反哺）                                          │
                     └──────────────────────────────────┬──────────────────────────────────────────┘
                                                         ▼  output/prediction.json
        ┌──────────────────────── 元层 Meta Layer（流水线之外）────────────────────┐
        │  Calibrate 回测校准 ──► model_params.json                                │
        │  Evaluator 预测复盘 ──► prediction_ledger.jsonl（留档）+ eval_report.json │
        │  Evolution 进化编排 ──► evolution_log.jsonl（只追加的进化史）             │
        └──────────────────────────────────┬───────────────────────────────────────┘
                                            ▼
                                 ┌──────────┴──────────┐
                                 │  FastAPI (api.py)   │  9 条 REST 路由 + 前端静态托管
                                 │  + auto-refresh 调度 │
                                 └──────────┬──────────┘
                                            ▼
                            ┌───────────────────────────────────┐
                            │  Vue 3 前端 SPA（5 视图）          │
                            │  对阵树/小组赛/概率榜/冠军推理/复盘 │
                            └───────────────────────────────────┘
```

原则：**预测流水线单向、无环依赖**；每个模块输入输出均为纯数据（dict/JSON），可独立测试、独立演示。
流水线之外有**元层**（meta layer）：Calibrate（回测校准，写 model_params.json 反哺 Rating/Predictor）、Evaluator（预测复盘）、Evolution（进化编排）——消费预测/账本/赛果，产出报告与参数变更，不侵入流水线本体。API 层带 auto-refresh 后台调度（见 §6）。

## 3. 模块职责与接口

### 3.1 Collector（数据采集）

| 项 | 说明 |
|---|---|
| 输入 | 无必需参数；`FOOTBALL_DATA_TOKEN` 可选（备用源） |
| 输出 | `{teams, groups, group_matches, bracket, match_details}`；match_details 含每场首发/黄红牌/换人 |
| 数据源 | **主**：Wikipedia MediaWiki API（wikitext 确定性解析）+ eloratings.net；**备**：football-data.org |
| 容错 | 每次成功在线采集写入 `backend/data/tournament.json` 快照；失败自动读快照并标记 `source: "snapshot"`；429/网络错误指数退避重试 |

### 3.2 Rating（实力评估）

| 项 | 说明 |
|---|---|
| 输入 | `TournamentData` |
| 输出 | `dict[team_id -> StrengthScore]`，含分项：`elo`、`fifa_rank`、`recent_form`（近期状态）、`wc_performance`（本届表现）、综合分 `overall` |
| 逻辑 | 加权融合，权重见复现指南 §3.1；纯函数，无外部调用 |

### 3.3 Predictor（单场概率预测）

| 项 | 说明 |
|---|---|
| 输入 | 两队 `StrengthScore` + 比赛属性（是否淘汰赛） |
| 输出 | `MatchPrediction`：`{p_win, p_draw, p_loss, most_likely_score, score_matrix, expected_goals}`；淘汰赛额外含 `p_advance`（含加时/点球） |
| 逻辑 | 实力差 → 期望进球 λ → 独立泊松比分矩阵（公式见复现指南 §3.2）；纯函数 |

### 3.4 Simulator（逐轮推演 + 蒙特卡洛）

| 项 | 说明 |
|---|---|
| 输入 | 当前赛况（已赛结果锁定为事实）+ Predictor |
| 输出 | ① 确定性推演：每轮每场"最可能结果"直至冠军；② 蒙特卡洛：10,000 次全赛事模拟 → `dict[team -> p_champion]` 及进入各轮概率 |
| 逻辑 | 已赛场次直接采用真实结果；未赛场次按 Predictor 概率推进。固定随机种子保证可复现 |

### 3.5 Reasoner（LLM 推理解释）

| 项 | 说明 |
|---|---|
| 输入 | 单场/冠军的全部量化依据（实力分项、历史交锋、概率结果） |
| 输出 | 中文推理文本 |
| 模型 | 单场解说 `qwen-plus`；冠军长文 `qwen-max`（DashScope OpenAI 兼容接口，`DASHSCOPE_API_KEY`） |
| 约束 | **LLM 不产生数字结论，只解释统计模型的输出**；prompt 模板见复现指南 §4 |
| 降级 | 无 key / 调用失败 → 基于规则模板生成解释，标记 `reasoning_source: "template"` |

### 3.6 Features（上下文特征，v1.1-v1.6）

| 项 | 说明 |
|---|---|
| 输入 | 推演后的 bracket + tournament（含 match_details） |
| 输出 | 未赛场次的 `match.context`：`rest_days`（休息天数，F2 用小组赛日期初始化）、`prev_extra_time`（加时疲劳 F1）、`pens_this_wc`（本届点球）、`discipline`（停赛/黄牌预警）、`lineup`（首发稳定性）、`venue`（海拔/半主场/旅行距离 F5）、`form_trend`（本届状态趋势 F6）；核心球员表加载 |
| 约束 | 特征只进解释层（Qwen 上下文 + 前端量化依据），经 walk-forward 验证增益后才进评分层（docs/04、06） |

### 3.7 Calibrate（参数校准，元层，v1.2/v1.5）

| 项 | 说明 |
|---|---|
| 输入 | 全部已赛场次（预测用赛前实力分，无泄漏）；可注入自定义搜索网格 |
| 逻辑 | 阶段1网格搜索 goal_exp × rho × elo_div × w_form（样本内对数损失）；阶段2 **walk-forward** 前瞻搜索本届表现项 w_wc × adj_gd（逐场只用赛前数据，防过拟合） |
| 输出 | 两阶段各自改善超阈值（0.005）才写 `data/model_params.json`；predictor/rating 启动时自动加载 |

### 3.8 Evaluator（Eval Agent，元层，v1.7）

| 项 | 说明 |
|---|---|
| 输入 | prediction.json（实际赛果）+ prediction_ledger.jsonl（历史赛前预测） |
| 逻辑 | 留档未赛预测（幂等，同参数版本不重复）；对"有赛前预测且已完赛"的比赛做结果层/概率层/校准表复盘，诊断系统性偏差 |
| 输出 | `eval_report.json`（逐场对照 + 汇总 + 校准表 + goal_bias 诊断） |

### 3.9 Evolution（Evolution Agent，元层，v1.8）

| 项 | 说明 |
|---|---|
| 输入 | tournament + 上轮 prediction + 上轮 eval_report |
| 逻辑 | 读 Eval 诊断 → 标准安全校准（自动，过 walk-forward 门禁）→ 偏差产出**带推理提案**（不自动执行）→ 记进化日志 → finalize 回填冠军概率变化 |
| 输出 | `evolution_log.jsonl`（只追加的进化史）；安全边界：只改白名单参数、必过校准门禁、日志不可改 |

### 3.10 Pipeline（编排）

`python -m agent.pipeline [--refresh]` 依序执行：Collector →（--refresh 时 Evolution 进化闭环）→ Rating →（Predictor+Simulator）→ Features → Reasoner → 写 `prediction.json` → Evaluator 留档+复盘 → Evolution.finalize。`prediction.json` 是前后端唯一契约。

## 4. API 契约（FastAPI）

| 方法 | 路径 | 说明 |
|-----|------|-----|
| GET | `/api/prediction` | 完整预测结果（prediction.json 全量） |
| GET | `/api/bracket` | 淘汰赛对阵树（含已赛真实结果与未赛预测） |
| GET | `/api/groups` | 小组赛积分表与出线情况 |
| GET | `/api/champion` | 冠军预测 + 夺冠概率 Top16 + 推理长文 + 模型档案 |
| GET | `/api/match/{match_id}` | 单场详情：概率、比分矩阵、推理文本 |
| GET | `/api/eval` | 预测复盘报告（Eval Agent） |
| GET | `/api/evolution` | 进化时间线（Evolution Agent，只追加日志） |
| POST | `/api/refresh` | 重跑流水线（重新采集数据、进化校准、重预测） |
| GET | `/` | 前端 SPA（静态托管 `frontend/dist`） |

## 5. 前端结构

单页五个视图（顶部 Tab 切换）：

1. **淘汰赛对阵树**（默认页）：SVG bracket（32 强→16 强→8 强→4 强→决赛）。已赛场次绿框 + 真实比分 + "✓"；未赛场次蓝框 + 预测比分 + 晋级概率条；预测晋级路径高亮到冠军。点击场次 → MatchDetail 弹窗（胜平负概率条 + 比分矩阵热力 + 量化依据表 + 推理文本）。
2. **小组赛回顾**：12 组积分表，出线队高亮。
3. **夺冠概率**：Top 16 概率横向条形图，冠军金色高亮；附"进四强/进决赛/夺冠"三列概率表。
4. **冠军推理**：预测冠军大卡片 + Qwen 推理长文 + 模型档案（参数来源/校准样本/对数损失）+ 回测可信度。
5. **预测复盘**：Eval 复盘（5 指标卡 + 校准表 + 逐场对照）+ Evolution 进化时间线（可回放的模型自我改进史）。

## 6. 部署架构（阿里云）

```
用户浏览器 ──HTTP:80──► 阿里云 ECS
                          └── Docker 容器（单容器）
                               └── uvicorn :8000
                                    ├── /api/*  → FastAPI
                                    └── /*      → frontend/dist 静态文件
```

- **Dockerfile 多阶段构建**：stage1 `node:20` 构建前端 → stage2 `python:3.12-slim` 装后端依赖 + 拷贝 dist + 数据快照。
- 环境变量：`DASHSCOPE_API_KEY`（Qwen）、`FOOTBALL_DATA_TOKEN`（备用数据源）、`AUTO_REFRESH_MINUTES`（自动刷新间隔，默认 30，0=关闭），均可缺省。
- `deploy/deploy-ecs.sh`：安装 docker → 构建镜像 → `docker run -d -p 80:8000`。
- **auto-refresh 后台调度（v1.1）**：服务启动即拉起 asyncio 任务，定期在线探测；发现新完赛场次 → 更新快照 → 重跑全流程 → 热替换 API 缓存。比赛日无需人工干预。

## 7. 容错与降级矩阵

| 故障 | 行为 | 用户可见性 |
|-----|------|----------|
| 主数据源（Wikipedia）失败 | 读本地快照 | 页面标注数据源=快照 + 时间 |
| DashScope 失败/无 key | 模板化规则解释 | 推理文本仍完整，标注来源 |
| 快照也缺失 | 使用仓库内置的打包快照（随代码提交） | 正常演示 |
| 校准/进化/复盘异常 | try 包裹，不影响主预测产物 | 预测正常，元层缺该轮数据 |
| 前端拉 API 失败 | 显示错误态 + 重试按钮 | 明确报错 |

## 8. 测试策略

- **单元测试（pytest，39 个，7 个文件）**：predictor 概率自洽/对称性/DC 修正方向；simulator 固定种子可复现、已赛结果锁定、回测无泄漏；collector 快照结构与对阵/阵容解析；features 用合成对阵树（不随赛事推进失效）覆盖停赛/首发/场地/趋势；calibrate 对数损失区间与参数回读；evaluator 复盘用例与偏差检测；evolution 诊断阈值、不自动改 base_goals、方向冲突识别、日志追加。
- **端到端**：`python -m agent.pipeline` 离线跑通（纯快照模式）→ API 各路由 200 → 前端 build 成功 → 浏览器实测五视图与弹窗。
