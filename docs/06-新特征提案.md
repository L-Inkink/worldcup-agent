## 1. 提案清单

### F1 加时疲劳（aet fatigue）🟢🟢

- **现状缺口**：`rest_days` 只算日历天数，但上一场踢满 120 分钟（加时）与 90 分钟的恢复负荷完全不同。
- **数据来源**：bracket 每场已有 `aet` 标记（collector 已解析），零新数据。
- **实现位置**：`features.py::annotate_context`，在 `ctx["rest_days"]` 旁新增 `prev_aet: {home: bool, away: bool}`，或直接合成"有效疲劳"摘要。
- **注入**：解释层（Qwen 上下文 + 前端量化依据表）。
- **工作量**：小（~1 小时含测试）。

### F2 修复 32 强赛 rest_days 缺口 🟢🟢（这是 bug 级缺口，非新特征）

- **现状缺口**：`annotate_context` 的 `last_played` 仅从淘汰赛链（ROUND_CHAIN）开始积累，**32 强赛全部没有 rest_days**——而各小组末轮日期实际相差 2-3 天，恰是淘汰赛首轮的真实优势项。
- **原因**：`_parse_football_boxes` 未提取小组赛日期（Wikipedia footballbox 的 wikitext 中含日期字段）。
- **实现**：collector 补一个日期正则 → `group_matches` 带 `date` → `annotate_context` 先扫小组赛末轮初始化 `last_played`。
- **工作量**：小；需重跑一次在线采集刷新快照。

### F3 对手强度调整净胜球（opponent-adjusted GD）🟢

- **现状缺口**：`rating.py` 的 `wc_performance` 用裸净胜球——5:0 赢弱旅与 1:0 赢强敌同权。
- **实现**：每场净胜球按对手 Elo 加权（如乘 `opp_elo / 平均Elo`，或按 Elo 期望的超额表现），得 `wc_performance_adj`。
- **路径**：先并列展示在解释层；同时加入 calibrate.py 网格搜索空间，与现 `w_wc` 项做 A/B 回测——是少数有希望改善 log loss 的评分层候选。

### F4 攻防分离（attack / defense split）🟢

- **现状缺口**：评分只用 gd，`expected_goals` 只吃实力差——两支净胜球相同但"大开大合 vs 铁桶防守"的队得到相同 λ。经典 Maher/Dixon-Coles 本就是每队独立攻击强度 + 防守弱度参数。
- **数据来源**：小组积分表 gf/ga + 已赛淘汰赛比分，全部已有。
- **实现**：解释层先出 `wc_attack`（场均进球）/ `wc_defense`（场均失球）/ `clean_sheets`（零封场次）；评分层改造（λ_A 由 A 攻击 × B 防守合成）风险较高，须经校准验证后才动 predictor。

### F5 场地静态特征表（venue features）🟡→🟢

- **数据来源**：bracket 每场已有 `venue`；人工整理一张 16 主办城市静态表（海拔、经纬度、时区、气候带），一次成本永久复用。
- **推导特征**（均为解释层）：
  | 特征 | 说明 |
  |---|---|
  | `altitude` | 高原适应——墨西哥城阿兹特克 ~2240m、瓜达拉哈拉 ~1500m，世界杯史上真实影响项 |
  | `travel_km` / `tz_shift` | 连续两场 venue 经纬度算旅行距离与跨时区数（美国东西海岸 4000+ km） |
  | `host_home` | 东道主半主场——MEX/USA/CAN 在本国场地比赛，直接由数据判定（替代 doc 05 中靠搜索的 `home_crowd_advantage` 方案） |
- 备注：doc 04 全景表提过"旅行距离"，此前未排进任何 P 级计划，此处正式立项。

### F6 本届状态趋势（form trend）🟡

- **现状缺口**：`wc_performance` 是全届平均，抹平了"渐入佳境 vs 高开低走"。
- **实现**：小组赛三场按时间排序，取末场与首场表现差（或逐场净胜球斜率），输出定性标签供 Qwen 引用。依赖 F2 的小组赛日期解析（或按 Wikipedia 页面内顺序近似）。
- **仅进解释层**，样本太小（3 场），不做评分层候选。
