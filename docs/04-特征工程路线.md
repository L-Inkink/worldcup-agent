# 特征工程路线图

> 目标特征体系（长期）与落地优先级（按数据可得性分层）。
> 核心原则：**新特征先进解释层（Qwen 推理上下文 + UI 量化依据），经回测验证有增益后才进评分层（strength 公式）**——未经校准的特征权重会污染概率输出。

## 1. 目标特征体系（全景）

| 一级特征 | 二级特征示例 | 规模 | 数据源候选 | 可得性 |
|---------|------------|-----|-----------|--------|
| Team | Elo、FIFA、近10场、xG、净胜球 | 40+ | eloratings✅ / FIFA✅ / FBref | 高（xG 除外） |
| Player | 身价、年龄、位置、评分、状态 | 100+ | Transfermarkt / SofaScore | 低（需爬虫+反爬处理） |
| Lineup | 首发、阵型、伤病、替补深度 | 30+ | 赛前1小时官方公告 | 低（实时性要求极高） |
| Coach | 胜率、阵型、执教经验、战术风格 | 20+ | Wikipedia / Transfermarkt | 中（半静态可人工整理） |
| Chemistry | 共踢场次、国家队磨合、俱乐部配合 | 50+ | 需要逐球员交叉统计 | 极低 |
| Match | 天气、休息天数、裁判、场地、旅行距离 | 20+ | 赛程表✅ / 天气API | 高（休息/场地已有数据） |
| History | H2H、世界杯经验、点球大战表现 | 20+ | eloratings / 本届数据✅ | 中 |

## 2. 落地优先级

### P0 已实现（v1.1-v1.6，从已有数据零成本推导）

均落在 `match.context` → Qwen 推理上下文 + 前端量化依据表。详细设计与 F 编号见 [06-新特征提案.md](./06-新特征提案.md)：

- ✅ `rest_days`：休息天数（v1.1；F2 v1.5 起用小组赛日期完整初始化）
- ✅ `pens_this_wc`：本届点球大战胜负记录（v1.1）
- ✅ `prev_extra_time`：加时疲劳，上一场踢满120分钟（F1，v1.5）
- ✅ `discipline`：停赛风险 / 黄牌预警（M0，v1.4，需 collector 先解析阵容黄牌）
- ✅ `lineup`：首发稳定性 / 后防组合连续场次（M0，v1.4）
- ✅ `venue`：高海拔 / 东道主半主场 / 连续场地旅行距离（F5，v1.6）
- ✅ `form_trend`：本届状态趋势（渐入佳境/高开低走/表现平稳，F6，v1.6）

### P1 部分已实现（v1.2）

- ✅ 关键球员可用性表 `backend/data/key_players.json`（status: fit/doubt/out，注明数据日期，人工维护）——已注入 Qwen 推理上下文
- ⬜ 教练画像（大赛经验/战术风格标签），供 Qwen 推理引用
- ⬜ 世界杯历史点球大战记录（静态整理）

### P2 校准后进评分层（v1.2/v1.5 校准通道 + walk-forward 门禁）

- ✅ `calibrate.py`：两阶段校准（样本内网格搜索 + walk-forward 前瞻），产物 `model_params.json` 被 predictor/rating 自动加载
- ✅ Dixon-Coles 低比分修正（rho 由校准选定 -0.12）
- ✅ **F3 对手强度调整净胜球——经 walk-forward 否决**（w_wc=0）：本届表现与实时 Elo 重复计数，是一个诚实的负结果（详见 06）
- ⬜ rest_days 等上下文特征加入 strength 的增益验证（走同一 walk-forward 门禁）
- ⬜ H2H 历史交锋修正

### P3 远期（需新数据源/爬虫工程）

- xG（FBref）、球员身价（Transfermarkt）、首发阵容实时抓取、天气 API、传球网络

## 3. 主动数据调度（v1.1 已实现）

后端启动时拉起后台任务：每 `AUTO_REFRESH_MINUTES`（默认 30）分钟在线探测一次；
发现新完赛场次 → 更新快照 → 自动重跑全流程（进化校准→推演→特征→解释→复盘）→ 热替换 API 缓存。
比赛日无需人工干预，页面数据自动跟上真实赛程；设 `AUTO_REFRESH_MINUTES=0` 关闭。
