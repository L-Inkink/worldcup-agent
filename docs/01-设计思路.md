# 世界杯冠军预测 Agent —— 设计思路

> 本文档记录项目的目标、关键设计决策及其理由。配套文档：
> - [02-系统架构.md](./02-系统架构.md) —— 模块划分、数据流、接口契约
> - [03-复现指南.md](./03-复现指南.md) —— 算法公式、数据源、实现步骤，供任何人/任何 AI 工具独立复现本工程

## 1. 背景与赛题要求

本项目为 Agent 开发比赛参赛作品。赛题核心要求：

| 能力维度 | 赛题要求 |
|---------|---------|
| 数据采集 | 获取世界杯相关数据（历史战绩、球队排名、球员信息、分组等），来源不限 |
| 分析决策 | 自主设计预测逻辑与决策链路：小组赛分析 → 淘汰赛逐层推演 → 决赛预测，推理过程可解释 |
| 结果输出 | 从小组赛到决赛的逐轮预测结果与推理依据，预测最终冠军 |
| 可视化 | 页面展示赛程树/对阵图、各轮比分预测 |

加分项：① 部署阿里云对外提供互动；② 全链路使用 Qwen 模型。

**注意（流程合规）**：赛题硬性要求开发全流程使用 Qoder/QoderWork，路演 PPT 须用 QoderWork 制作。工程实现本身与工具无关，但参赛者应在 Qoder 中操作以保留使用痕迹。

## 2. 核心决策与理由

### 决策 1：预测目标 —— 2026 美加墨世界杯（进行中，实时推演）

项目开发时间为 2026 年 7 月初，2026 世界杯（48 队，2026-06-11 至 2026-07-19）正处于淘汰赛阶段：小组赛已全部结束，32 强/16 强赛正在进行。

选择"实时推演"而非历史复盘（如 2022 卡塔尔）的理由：

- **时效性与话题性**：预测正在进行的赛事，演示时观众可以对照真实进程验证，冲击力远超复盘。
- **天然的校准数据**：小组赛与已完成淘汰赛的真实结果可用于校准模型（各队本届实际表现纳入实力评估），也可以展示"模型对已赛场次的预测准确率"作为可信度证据。
- **完整决策链路仍然保留**：对已赛部分展示"真实结果 + 模型回测"，对未赛部分展示"逐轮预测推演"，赛题要求的"小组赛→淘汰赛→决赛"链路完整覆盖。

### 决策 2：技术栈 —— Python 后端 + Vue 3 前端

- **后端 FastAPI**：Python 是数据分析/统计建模的最优生态（泊松分布、蒙特卡洛用 numpy/scipy 即可）；FastAPI 自带 OpenAPI 文档，答辩演示接口方便；部署阿里云 ECS 成熟简单。
- **前端 Vue 3 + Vite + 原生 SVG**：对阵树（bracket）用 SVG 手绘完全可控，不引入重型图表库，构建产物小，由 FastAPI 直接托管静态文件，**单容器单端口**即可对外服务，部署最简。
- 不选 Next.js 全栈：预测建模在 Node 生态弱；不选纯静态页面：无法体现"对外提供互动"加分项。

### 决策 3：预测引擎 —— 统计模型为骨架，LLM 负责解释

**"数字由统计模型算，文字由 LLM 写"**，两者严格分工：

- **统计骨架（可复现、可自洽）**：Elo 实力评分 → 期望进球数 λ → 泊松分布比分概率矩阵（Dixon-Coles 低比分修正）→ 胜/平/负概率 + 最可能比分；淘汰赛叠加加时/点球模型；整届赛事跑 10,000 次蒙特卡洛模拟得到每队夺冠概率分布。模型参数不靠拍脑袋：由已赛场次回测（对数损失网格搜索 + walk-forward 前瞻验证）自动校准。一个诚实的负结果：本届表现项（净胜球）曾试图进评分层，但 walk-forward 证明它与实时 Elo 重复计数，权重被校准为 0（见 [04](./04-特征工程路线.md) F3）。
- **LLM 解释层（可解释性）**：把每场预测的量化依据（实力分、历史交锋、近期状态、本届表现）作为上下文喂给 Qwen，生成中文推理文本。LLM **不产生任何数字结论**，只解释数字。

理由：纯 LLM 预测不可复现、概率不自洽，答辩被追问方法论时站不住；纯 ML（如 XGBoost）特征工程重、世界杯样本少易过拟合。泊松模型是足球预测领域公认的经典基线（Maher 1982 起），方法有出处、可解释、实现成本低。

### 决策 4：数据采集 —— Wikipedia 为主源，本地快照兜底

- **主数据源：Wikipedia**（MediaWiki API 拉 wikitext 确定性解析——赛程/分组/实时赛果/完整对阵树/阵容与黄牌，无需 API key）+ **eloratings.net**（国家队 Elo 评分）+ FIFA 排名静态表。football-data.org 为**可选备用源**（需 token）。
- **每次成功拉取都将数据落盘为本地 JSON 快照**；数据源不可用（断网/限流）时自动降级读取快照，快照随仓库提交。演示现场零风险。
- 采用确定性解析（而非 LLM 抽取）保证赛果准确、不幻觉；同一解析逻辑随赛事推进自动带出新完赛结果，是 auto-refresh 的基础。

### 决策 5：元层双 Agent —— Eval 复盘 + Evolution 进化

预测流水线之外设**元层（meta layer）**，消费预测/账本/赛果，产出报告与参数变更，不侵入五模块流水线本体：

- **Eval Agent**（`evaluator.py`）：赛前预测留档账本 + 逐场复盘（结果层/概率层/校准表），诊断系统性偏差。
- **Evolution Agent**（`evolution.py`）：进化闭环编排（Eval 诊断→安全校准→可审计进化日志）。刻意采用**克制形态**——参数自动变更只走带 walk-forward 门禁的校准，Eval 诊断出的偏差只产出**带推理的提案交人工**，不自动改概率模型（理由见 [07](./07-Eval与Evolution-Agent方案.md) 的自我质疑）。

### 决策 6：两个加分项都做

- **Qwen 全链路**：推理解释接阿里云 DashScope，单场解说用 `qwen-plus`（快、便宜），冠军预测长文推理用 `qwen-max`（质量高）。无 API key 时降级为模板化规则解释，功能不残缺。
- **阿里云部署**：全项目 Docker 化为单镜像，附 ECS 一键部署脚本与文档。

## 3. 成功标准

1. 打开页面即见完整世界杯对阵树：已赛场次显示真实比分，未赛场次显示预测比分与胜率，点击任意场次可见推理依据。
2. 冠军预测页给出：预测冠军、Top 16 夺冠概率分布（蒙特卡洛）、Qwen 生成的完整推理长文。
3. 后端 `python -m agent.pipeline` 可离线一键复跑全流程（采集→进化校准→评估→推演→特征→解释→留档复盘），结果落盘 JSON。
4. `docker run` 一条命令即可在任意机器（含阿里云 ECS）拉起完整服务。
5. 模型对已赛场次的胜负预测命中率可在「预测复盘」页查证（当前 93 场回测 73%）；每场赛前预测留档账本，可逐场对照赛后结果。

## 4. 明确不做（YAGNI）

- 不做球员级**自动化数据抓取**（Transfermarkt 身价/实时首发爬虫）——成本高且脆弱。折中方案已实现：人工维护的核心球员可用性表（`key_players.json`）注入推理解释层，见 [04-特征工程路线.md](./04-特征工程路线.md) P1。
- 不做用户账号/收藏等产品功能——与赛题无关。
- 不做实时比分推送（WebSocket）——后台 auto-refresh 定时探测新赛果并自动重跑预测（v1.1），页面刷新即见最新。
- 不训练机器学习模型——样本少、周期风险高，见决策 3；但模型超参由回测数据校准（v1.2）。
